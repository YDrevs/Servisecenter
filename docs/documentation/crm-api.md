# API заявок LeaderAuto — для розробника CRM

REST API, через яке CRM забирає заявки із сайту та змінює їм статус і нотатку.
Дані клієнта (ім'я, телефон, авто, повідомлення) через API не змінюються, їх задає лише форма на сайті.

Базова адреса: `https://<домен>/wp-json/leaderauto/v1`

## Автентифікація

Кожен запит має містити заголовок:

```
X-Api-Key: <ключ>
```

Ключ видає адміністратор сайту: змінна середовища `LEADERAUTO_CRM_API_KEY` на сервері
або поле **CRM API key** у wp-admin → Налаштування → LeaderAuto. Ключ має бути не коротшим
за 32 символи, згенерувати його можна так: `openssl rand -hex 32`. Працюйте лише через HTTPS.

| Відповідь | Причина |
|---|---|
| `401 leaderauto_api_unauthorized` | заголовка немає або ключ хибний |
| `503 leaderauto_api_disabled` | на сайті ключ не задано, тобто API вимкнено |

## Заявка

```json
{
  "id": 152,
  "created_at": "2026-10-17T10:33:10+03:00",
  "updated_at": "2026-10-17T12:30:00+03:00",
  "name": "Олена",
  "phone": "095 066 29 21",
  "phone_digits": "0950662921",
  "car": "Tesla Model 3",
  "message": "Заміна гальмівної рідини",
  "status": "la_progress",
  "status_label": "В роботі",
  "note": "Передзвонив, записав на понеділок",
  "admin_url": "https://<домен>/wp-admin/post.php?post=152&action=edit"
}
```

| Поле | Опис |
|---|---|
| `id` | стабільний ідентифікатор, ключ для upsert |
| `created_at` / `updated_at` | ISO 8601 у часовому поясі сайту |
| `phone` | як ввів клієнт; `phone_digits` — лише цифри (для пошуку й дедуплікації) |
| `car`, `message`, `note` | можуть бути порожніми рядками |
| `status` | `la_new` Нова · `la_progress` В роботі · `la_done` Виконана · `la_cancel` Скасована · `trash` У кошику (лише читання) |

Текст віддається як є, без HTML-сутностей: `&` приходить як `&`, а не `&amp;`.

`updated_at` змінюється при: створенні заявки, зміні статусу, збереженні картки в адмінці,
`PATCH` через API, переміщенні в кошик і відновленні з кошика.

## `GET /leads` — список

| Параметр | За замовчуванням | |
|---|---|---|
| `updated_since` | — | ISO 8601; повертає заявки з `updated_at >=` цієї дати (межа включна) |
| `status` | усі, включно з `trash` | список через кому: `la_new,la_progress` |
| `page` | `1` | |
| `per_page` | `50` | максимум `100` |

Сортування: `updated_at` за зростанням, далі `id` за зростанням.

```bash
curl -s -H "X-Api-Key: $KEY" \
  "https://<домен>/wp-json/leaderauto/v1/leads?updated_since=2026-10-17T10:00:00%2B03:00&per_page=100"
```

```json
{ "items": [ { …заявка… } ], "page": 1, "per_page": 100, "total": 3, "total_pages": 1 }
```

У query-рядку `+` треба кодувати як `%2B`, інакше він стане пробілом. Можна передавати дату в UTC: `2026-10-17T07:00:00Z`.

Помилки: `400 leaderauto_bad_request` (невалідна дата або статус), `400 rest_invalid_param` (`page` / `per_page` поза межами).

## `GET /leads/{id}` — одна заявка

```bash
curl -s -H "X-Api-Key: $KEY" https://<домен>/wp-json/leaderauto/v1/leads/152
```

`404 leaderauto_lead_not_found`, якщо заявки немає. Заявки з кошика повертаються зі `status: "trash"`.

## `PATCH /leads/{id}` — статус і/або нотатка

```bash
curl -s -X PATCH -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  https://<домен>/wp-json/leaderauto/v1/leads/152 \
  -d '{"status": "la_done", "note": "Авто видано клієнту"}'
```

| Поле | Правило |
|---|---|
| `status` | `la_new`, `la_progress`, `la_done` або `la_cancel` |
| `note` | рядок до 2000 символів, **повністю замінює** нотатку; HTML-теги вирізаються |

Обидва поля необов'язкові, але хоча б одне передати треба. Відповідь `200` — оновлена заявка.

| Помилка | Причина |
|---|---|
| `400 leaderauto_bad_request` | ні `status`, ні `note` не передано |
| `404 leaderauto_lead_not_found` | заявки немає |
| `409 leaderauto_lead_trashed` | заявка в кошику — змінювати не можна |
| `422 leaderauto_invalid` | недопустимий статус або задовга нотатка; деталі — у `data.fields` |

Зміна статусу через API запускає ту саму подію `lead.status_changed` у Make.com, що й зміна
в адмінці сайту. Тому сценарії в Make (наприклад, SMS «авто готове») спрацюють і на статус, поставлений у CRM.
Якщо змінилась лише нотатка, подія не надсилається.

## Синхронізація — рекомендований алгоритм

1. **Перший запуск:** `GET /leads?per_page=100` без `updated_since`, гортати `page` до `total_pages`.
2. Запам'ятати найбільший `updated_at` серед отриманих заявок (курсор).
3. **Кожні N хвилин:** `GET /leads?updated_since=<курсор>&per_page=100`, гортати сторінки, оновити курсор.
4. Записувати заявки в CRM через **upsert за `id`**. Межа `updated_since` включна, тому заявки
   з тим самим `updated_at`, що й курсор, прийдуть повторно, і це нормально.
5. `status: "trash"` означає, що заявку прибрали на сайті, і в CRM її варто позначити так само.
   Остаточне видалення з кошика через API не відстежується.

Ліміту частоти запитів немає, але опитування частіше ніж раз на хвилину не має сенсу.
