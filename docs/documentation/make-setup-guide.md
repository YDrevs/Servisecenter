# Підключення заявок до Make.com

Сайт сам надсилає заявки в Make.com — нічого опитувати не треба. Достатньо створити в Make
сценарій із вебхуком і вписати його адресу на сайті.

## 1. Вебхук у Make

1. Make → **Create a new scenario** → модуль **Webhooks → Custom webhook**.
2. **Create a webhook** → назва, наприклад `LeaderAuto — заявки`.
3. Рекомендовано: **Show advanced settings → API Key authentication → Add** — створіть ключ і
   скопіюйте його. Без ключа будь-хто, хто дізнається адресу, зможе надсилати в сценарій підроблені заявки.
4. **Save** → скопіюйте адресу вигляду `https://hook.eu2.make.com/…`.

## 2. Адреса на сайті

wp-admin → **Налаштування → LeaderAuto**:

- **Make.com webhook URL** — адреса з кроку 1 (лише `https://`).
- **Make.com API key** — ключ з кроку 1, якщо створювали.
- **Зберегти зміни**.

На сервері (Railway) замість полів можна задати змінні середовища
`LEADERAUTO_MAKE_WEBHOOK_URL` і `LEADERAUTO_MAKE_API_KEY` — тоді поля на екрані неактивні.

## 3. Показати Make структуру даних

1. У Make, у модулі вебхука, натисніть **Redetermine data structure** — Make чекає запит.
2. На сайті, під налаштуваннями, натисніть **Надіслати тестову подію**. Має з'явитися
   «Тестову подію надіслано, Make відповів 200».
3. У Make з'явиться **Successfully determined** — тепер усі поля доступні для мапінгу.

Тестова подія має `test = true` і `lead.id = 0`. Відфільтруйте її в сценарії, щоб вона не
потрапила в таблицю чи CRM.

## 4. Події

| `event` | Коли |
|---|---|
| `lead.created` | клієнт надіслав форму на сайті |
| `lead.status_changed` | менеджер змінив статус заявки (у картці або масово) |

Обидві події надходять на одну адресу. Розгалужуйте сценарій **Router**-ом із фільтром
за полем `event`, наприклад:

- `event = lead.created` → додати рядок у Google Sheets / повідомити менеджера;
- `event = lead.status_changed` **і** `lead.status = la_done` → SMS / Viber клієнту «авто готове».

## 5. Поля

| Поле | Приклад |
|---|---|
| `event` | `lead.created` |
| `sent_at` | `2026-10-17T12:30:00+03:00` |
| `site` | адреса сайту |
| `previous_status` | лише в `lead.status_changed`: `la_new` |
| `test` | лише в тестовій події: `true` |
| `lead.id` | `152` — номер заявки, стабільний ключ для таблиць і CRM |
| `lead.created_at` | дата заявки |
| `lead.updated_at` | дата останньої зміни заявки |
| `lead.name`, `lead.phone`, `lead.car`, `lead.message` | як написав клієнт |
| `lead.phone_digits` | телефон лише цифрами: `0950662921` |
| `lead.status` | `la_new` · `la_progress` · `la_done` · `la_cancel` |
| `lead.status_label` | Нова · В роботі · Виконана · Скасована |
| `lead.note` | нотатка менеджера |
| `lead.admin_url` | посилання на картку заявки в адмінці |

Дати — у часовому поясі сайту (Налаштування → Загальні → Часовий пояс; для Чернівців — «Київ»).

## Якщо Make не отримує заявки

- У картці заявки, блок **Доставка**: `Make.com: ✓` — дійшло; `✗` — Make не відповів або
  повернув помилку; `—` — URL не вказаний. Поруч — час останньої спроби.
- При помилці сайт повторює спробу через 1, 5 і 30 хвилин. Повтори запускає WP-Cron, який
  спрацьовує, коли хтось відкриває сайт, тож на тихому сайті повтор може трохи запізнитися.
- Сценарій у Make має бути **увімкнений** (ON). Вимкнений сценарій Make приймає запити
  в чергу, але не обробляє.
