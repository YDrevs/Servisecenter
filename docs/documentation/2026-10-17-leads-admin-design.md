# Заявки з сайту в адмінці — дизайн

Дата: 2026-10-17 · Статус: погоджено

## Мета

Кожна заявка з контактної форми зберігається в БД і доступна в wp-admin: перегляд,
пошук, статус, нотатка менеджера. Це етап 1 з трьох:

1. **Заявки в адмінці** — цей документ.
2. Webhook у Make.com при новій заявці — окремий дизайн.
3. Захищений API для вивантаження заявок у CRM — окремий дизайн.

Етапи 2–3 спираються на сховище й статуси з етапу 1.

## Поточний стан

`POST /wp-json/leaderauto/v1/contact` (`includes/class-rest-contact.php`) валідує
`name`, `phone`, `car`, `message` і надсилає e-mail + Telegram. У БД нічого не пишеться.
Якщо обидва канали падають, клієнт отримує `502`, а заявка губиться.

## Рішення: Custom Post Type

Заявка = запис типу `la_lead`. Власна таблиця відкинута: на обсязі одного СТО виграшу
немає, а коду (схема, міграції, свій список, свої запити) у кілька разів більше.

### Дані

| Що | Де |
|---|---|
| Ім'я | `post_title` + meta `_la_name` |
| Телефон | meta `_la_phone` + `_la_phone_digits` (лише цифри — для пошуку) |
| Авто | meta `_la_car` |
| Повідомлення | `post_content` |
| Дата створення | `post_date` |
| Статус | `post_status` |
| Нотатка менеджера | meta `_la_note` |
| Доставка e-mail / Telegram | meta `_la_delivered_mail`, `_la_delivered_tg` (`1` / `0`) |

### Статуси

Реєструються через `register_post_status`:

| Ключ | Назва |
|---|---|
| `la_new` | Нова (присвоюється при створенні) |
| `la_progress` | В роботі |
| `la_done` | Виконана |
| `la_cancel` | Скасована |

Кошик (`trash`) — стандартний WordPress.

### Реєстрація CPT

`public => false`, `show_ui => true`, `show_in_rest => false`, `exclude_from_search => true`,
`supports => []` (без редактора — поля клієнта лише для читання),
`capability_type => 'post'` — доступ мають ролі з `edit_posts` (адміністратор, редактор).
Створення заявки вручну з адмінки вимкнено (`create_posts => 'do_not_allow'`).

## Потік збереження

У `Rest_Contact::handle()`:

1. Honeypot, throttle, валідація — без змін.
2. **Створити заявку** (`wp_insert_post`, статус `la_new`) — до відправки.
3. Відправити e-mail і Telegram, як зараз.
4. Записати результат доставки в meta.
5. Відповідь:
   - заявку збережено → `200` «Дякуємо», навіть якщо обидва канали не спрацювали;
   - збереження не вдалося і обидва канали не спрацювали → `502`, як зараз;
   - збереження не вдалося, але хоч один канал спрацював → `200`, помилка в `error_log`.

Throttle-транзієнт ставиться після успішної відповіді `200`.

## Адмінка

**Меню «Заявки»** (top-level, іконка `dashicons-email-alt`), з лічильником кількості
`la_new` у бейджі (`awaiting-mod`).

**Список** (стандартний `edit.php?post_type=la_lead`):

- Колонки: Дата · Ім'я · Телефон (`tel:`-посилання) · Авто · Повідомлення (перші ~80 символів) · Статус.
- Вкладки-фільтри за статусом — стандартні для зареєстрованих статусів (`show_in_admin_status_list`).
- Пошук: стандартний за title/content + телефон з meta (через `posts_search`/`posts_join` або `pre_get_posts`).
- Масова дія «Змінити статус → …» для кожного статусу (`bulk_actions-edit-la_lead`).
- Сортування за датою (за замовчуванням — найновіші зверху).

**Картка заявки** (`post.php`), метабокси:

- «Клієнт» — ім'я, телефон, авто, повідомлення, дата — лише для читання.
- «Обробка» — select статусу, textarea «Нотатка менеджера», кнопка «Зберегти».
- «Доставка» — e-mail ✓/✗, Telegram ✓/✗.

Збереження — `save_post_la_lead` з nonce і перевіркою `current_user_can( 'edit_post', $id )`;
статус приймається лише з білого списку.

## Файли

- **Новий:** `app/wp-content/plugins/leaderauto-core/includes/class-leads.php` — CPT, статуси,
  меню й лічильник, колонки, пошук, масові дії, метабокси, збереження. Публічний метод
  `Leads::create( array $payload ): int` (0 при помилці) і `Leads::set_delivery( int $id, bool $mail, bool $tg )`
  для REST-ендпоінта.
- **Змінений:** `leaderauto-core.php` — `require` + `( new Leads() )->hooks()`.
- **Змінений:** `includes/class-rest-contact.php` — виклики `Leads::create` / `set_delivery`,
  нова логіка відповіді.
- `uninstall.php` — **без змін**: заявки при видаленні плагіна не видаляються свідомо.

## Поза обсягом

Експорт CSV, редагування полів клієнта, призначення відповідального, email-сповіщення
про зміну статусу, Make.com і CRM-API (етапи 2–3).

## Перевірка

Тестового фреймворку немає — ручна перевірка на локальному оточенні:

1. `make site`, надіслати форму з `/contacts/` → заявка зі статусом «Нова» в адмінці, лічильник = 1.
2. `curl` на ендпоінт з невалідним телефоном → `422`, заявка не створена.
3. Honeypot `website` заповнений → `200`, заявка не створена.
4. Змінити статус і нотатку в картці → збереглися; лічильник зменшився.
5. Масова зміна статусу кількох заявок.
6. Пошук за частиною телефону.
7. Порожні налаштування доставки + недоступний mail → заявка все одно збережена, `200`,
   у «Доставка» ✗/✗.
8. Користувач без `edit_posts` (subscriber) меню не бачить.
